## 模型怎么改了

研究泊松、Dixon–Coles、负二项和预测不确定性后，在7月1日至9月28日355个共同样本上比较十种候选，冻结 `team-only-researched-v3`。详细来源和候选成绩见 [RESEARCH.md](RESEARCH.md) 与 `data/model.json`。

最终版仅取本场两队各自同赛事的历史比赛，目标日期前至少两天、过去365天内、每队最近最多12场。同主客权重1、另一主客权重0.5，180天半衰期。每队至少5场、同主客至少2场、有效样本量至少3，否则留空。可能跨赛季，这不等于使用其他队或联赛平均。

主队预期进球=（主队自身加权进球+客队自身加权失球）/2；客队反向同理。两队历史总进球加权方差除各自有效样本量，再除4相加，近似估计总强度不确定性，用负二项矩匹配生成总进球分布。该近似忽略两队样本重叠导致的协方差，不是完整贝叶斯拟合。没有联赛均值、大球率、先验、统一主场进球加成、盘口、外部推荐或目标赛果输入；赛事ID仅筛选自身历史，赛事名称仅显示。

单球格用统一绝对概率色阶：低于10%、10–20%、20–30%、30%以上；所有百分比同时保留文字，颜色不是唯一信息。右侧0–1合计蓝色，4+橙色，5+红色，6+紫色，合计列互有重叠，不能相加。前列标签按全部可预测场次分别取两端前三，仅为相对排名；前五按钮在当前赛事和搜索筛选内排名，不代表强信号。主选档仍可由预测接口输出，但不作为页面筛选目标。原data/picks.json保留为先前主选展示的审计记录。

## 复现和未来使用

Python 3.10+，仅标准库：

```sh
python model/validate.py
python model/validate_tails.py
python model/predict.py examples/future_case.json
python model/predict.py examples/historical_case.json --replay
python model/build_html.py
```

未来预测需先按 `data/provenance.json` 所列官方接口采集、验证双方uniformTeamId、赛事ID、实际比赛日期和90分钟进球，按 `examples/future_case.json` 格式输入。`predict.py` 拒绝已开赛场次，回放必须显式 `--replay`。此仓库是可复算快照及预测接口，**没有自动每日采集或实时刷新服务**。页面留档不会自动更新赛果。

`data/cases.jsonl` 是2466个目标的逐队标准化历史输入，`outcomes.json` 单独保存验证标签；预测接口不读取标签。`validation.json` 保留全部369个10月目标，包括277场可预测和92场资料不足。与旧算法的对照仅在共同214场比较，不能把覆盖扩大视作准确率提高。20天为10月11—30日，30天为10月1—30日，都是按目标日期截断的回顾性复算。模型调整前已看过部分10月结果，**不属于新的盲测，也不等于当时真实发布过的预测**；事后拉取历史资料无法证明当时页面可用性。下一步应冻结版本收集新赛前快照再检验。

## 已知不足

比分本身无法区分射门质量和运气；缺少一致口径的逐场xG、红牌分钟、球员出场分钟与可回放阵容数据。没有把未验证伤停人为换算成进球加减。样本跨赛季、主帅和阵容更换、升降级、历史对手强弱、同赛季杯赛主客中立场变化可能影响估计。默认模型不使用对手强度校正，候选未胜出。数据不足的杯赛或日韩场次照样留空，不采用联赛先验补齐。今日日本、韩国及澳洲早场已开赛，不补做赛前预测。

历史高概率组仍偏乐观，改进不是准确性保证。请保留全部失败和跳过项，而不是只看大球命中场。

以上仅为公开信息整理后的娱乐分析，不构成任何购彩建议，请理性参考。

尾部单独验证见data/tail-validation.json：分别计算0–1、4+、5+、6+的Brier、概率分箱和每日前五的实际发生率。全部结果来自已查看的10月回顾性数据，不作为新盲测或投注优势证明。
